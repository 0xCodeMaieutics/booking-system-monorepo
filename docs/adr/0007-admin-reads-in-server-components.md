# Admin Dashboard and Booking Site read data in server components

The Admin Dashboard fetches data in server components through the tRPC server caller and passes it to client components as props, instead of caching it on the client with React Query's `useQuery`. Mutations stay on tRPC (ADR 0003) and are followed by `router.refresh()`, which re-renders the whole route, so there are no hand-maintained cache invalidations to keep in sync. Page-level state that drives a read (date, search term) lives in the URL; lookups that depend on in-form state (available slots) call the tRPC client imperatively. `useQuery` and its siblings are banned in `apps/admin` and `apps/booking` by lint, even though React Query remains installed for `useMutation`.

The Booking Site follows the same rule. Its booking steps live in the URL, so the page reads the chosen Treatment's Practitioners and their Available Slots on the server; choosing a Treatment or Practitioner navigates through the router, while choosing a date or time only updates the URL because the slots are already loaded. After booking, the Manage Link's token is kept in a session cookie scoped to the confirmation URL so that page can render the Appointment on the server.
